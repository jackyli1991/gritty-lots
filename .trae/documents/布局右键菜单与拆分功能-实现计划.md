# 布局右键菜单与拆分功能实现计划

## 一、目标概述

在 [renderLayout.vue](file:///d:/workspace/gritty-lots/packages/page-neural/src/core/layout/renderLayout.vue) 上完成布局的右键菜单与结构编辑能力，覆盖用户规则 1–8：

1. 初始只有根 Splitter（无嵌套）；
2. Splitter 右键：水平拆分 / 垂直拆分 / 删除（根 Splitter 不可删）；
3. 拆分出的 Splitter 默认 2 个面板、`sizes [50, 50]`、面板单位默认 `%`；
4. SplitterPanel 右键：水平拆分 / 垂直拆分 / 在前面添加 / 在后面添加 / 删除；
5. 面板拆分 = 在该面板下新建 Splitter 再套用规则 3；前/后添加 = 在同级插入面板；删除 = 移除该面板；
6. 点击面板标签上的单位可循环切换 `px → % → vw → vh`；
7. Splitter 拖拽结束时，按每个面板自身的 `useUnit` 换算并写回 `sizeValue`；
8. 数据结构沿用用户给定结构（`sizeValue` + `useUnit`）。

已与用户确认的三点：a) Splitter 菜单由 Splitter 自身区域的右键触发、面板菜单由面板右键触发（互不干扰）；b) Splitter 拆分采用「包一层父 Splitter 并保留原有内容」；c) 单位枚举为 `px / % / vw / vh`（`vm` 视为 `vw` 笔误），交互为点击循环切换。

## 三、语义与结构设计（决策）

### 1. 节点工厂与工具（新增 `core/layout/utils.ts`）

```ts
export const DEFAULT_SPLIT_SIZES = [50, 50]; // 拆分默认占比
export const DEFAULT_PANEL_UNIT = '%'; // 新面板默认单位
export const UNIT_CYCLE = ['px', '%', 'vw', 'vh'] as const; // 单位切换顺序

generatePanelNode(overrides?): LayoutPanelNode      // { id, type:'splitterPanel', useUnit:'%', sizeValue:0, children: [] }
generateSplitterNode({ layout, children }): LayoutSplitterNode  // { id, type:'splitter', layout, sizes:[50,50], children }
isSplitterNode(children): children is LayoutSplitterNode        // 从组件内抽出，供多处复用
normalizeSizes(sizes): number[]                     // 按原比例归一到合计 100，保留 2 位小数
toSizeValue(axisPx, unit, containerPx): number      // 单位换算（见下）
```

### 2. 单位枚举与 `sizeValue` 换算（规则 6 / 7）

- 循环顺序：`px → % → vw → vh → px`。
- 基准 `axisPx`：面板沿所属 Splitter 轴向的真实像素（`layout: 'horizontal'` 取宽、`'vertical'` 取高），沿用现有 `getBoundingClientRect()` 测法。
- 换算规则：

| 单位 | `sizeValue`                                        |
| ---- | -------------------------------------------------- |
| `px` | `axisPx`，取整                                     |
| `%`  | `axisPx / 容器轴向像素 * 100`，保留 2 位小数       |
| `vw` | `axisPx / window.innerWidth * 100`，保留 2 位小数  |
| `vh` | `axisPx / window.innerHeight * 100`，保留 2 位小数 |

容器轴向像素来自本实例 Splitter 根元素（新增 `splitterRef`）。`vw` / `vh` 与布局方向无关，两者都按视口换算。

### 3. 空面板表示

面板无嵌套时 `children: []`（数组），有嵌套时 `children: <Splitter>`（对象），与 `LayoutPanelNode['children']` 联合类型一致。`isSplitterNode({})` / `isSplitterNode([])` 均为 false，容错旧数据。

### 4. 拆分语义（规则 3 / 5）

Splitter 拆分 = 包一层父 Splitter 并保留内容：

```ts
// 1) 复制原 Splitter（新 id，保留自己的 layout / sizes / 面板）
const oldContent = {
  ...node,
  id: generateId('l'),
  sizes: [...node.sizes],
  children: [...node.children],
};
// 2) 外层包一个选定方向的 Splitter：第 1 个面板装原内容，第 2 个为空面板
const wrapper = generateSplitterNode({
  layout,
  children: [generatePanelNode({ children: oldContent }), generatePanelNode()],
});
// 3) 落位：根节点原地替换（保持 store.layouts 与父级引用不变）；嵌套节点交给父面板
props.parent ? (props.parent.children = wrapper) : Object.assign(node, wrapper);
```

面板拆分（规则 5）：

```ts
const existing = isSplitterNode(panel.children) ? panel.children : null;
panel.children = existing
  ? wrapSplitter(existing, layout, panel) // 已有嵌套 Splitter：同样包一层，保留内容
  : generateSplitterNode({ layout, children: [generatePanelNode(), generatePanelNode()] });
```

- **在前面 / 在后面添加**：`generatePanelNode()` 插入到 `parentSplitter.children` 的 `index` / `index + 1`；`sizes` 同步 `splice(index, 0, 50)` 后 `normalizeSizes`。
- **删除面板**：`parentSplitter.children.splice(index, 1)`；`sizes` 同步删除后 `normalizeSizes`。
- **删除 Splitter**：根 Splitter 菜单项 `disabled: true`（规则 2）；嵌套 Splitter → `props.parent.children = []`（父面板保留、内容清空）。

### 5. 菜单项与图标

| 目标          | 菜单项（含图标）                                                                                                                                                                                                           |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Splitter      | 水平拆分 `Columns2` / 垂直拆分 `Rows2` / 分隔线 / 删除 `Trash2`（根禁用）                                                                                                                                                  |
| SplitterPanel | 水平拆分 `Columns2` / 垂直拆分 `Rows2` / 分隔线 / 在前面添加（横向 `ArrowLeftToLine`、纵向 `ArrowUpToLine`）/ 在后面添加（横向 `ArrowRightToLine`、纵向 `ArrowDownToLine`）/ 分隔线 / 删除 `Trash2`（同级仅剩 2 个时禁用） |

删除项沿用用户已写的红色 class（`[&>.p-contextmenu-item-content]:text-red-500! dark:...`）。图标按父 Splitter 的方向动态选择。

### 6. 标签与单位点击（规则 6）

- 标签文案改为 `{{ sizeValue }}{{ useUnit }}`，去掉原来的 `node.sizes[index]` 前缀：`sizes` 是 PrimeVue 内部占比，与 `sizeValue`（已按单位换算）语义重复，同屏显示易误导。
- 单位部分为独立可点击 `span`（`@click.stop`），`cursor-pointer` + hover 高亮（Tailwind、含 `dark:`）；点击后先切换 `useUnit`，再用当前测量值按新单位重算该面板 `sizeValue`，标签立即同步。

### 7. 共享菜单与动态菜单项

沿用「最外层实例唯一持有 ContextMenu」的既有方案，把注入函数签名升级为可携带菜单项：

```ts
type OpenMenu = (event: Event, items: MenuItem[]) => void;
const injectedOpen = inject<OpenMenu | null>('layout-context-menu', null);
const menuItems = ref<MenuItem[]>([]);
function openMenu(event: Event, items: MenuItem[]) {
  menuItems.value = items;
  menuRef.value?.show(event);
}
if (!injectedOpen) provide('layout-context-menu', openMenu);
const open = injectedOpen ?? openMenu; // 各实例统一调用
```

- 各实例在右键时**本地构建带上下文的 `menuItems`**（command 闭包捕获目标节点：面板 handler 捕获 `panel` + `props.node`（父 Splitter）；Splitter handler 捕获 `props.node` + `props.parent`），再 `open(event, items)`。这样共享菜单仍只有 1 个实例，但命令操作的是被右键的那个节点。
- 根 Splitter 判定：`props.parent` 为空即根（同时用于删除禁用与拆分落位），因此 `Splitter` 的删除项在根实例上 `disabled`。

## 五、假设与决策

1. **删除嵌套 Splitter** = 清空其父面板的 `children`（面板本身保留，可再次拆分），而不是删除该面板。
2. **面板删除保底 2 个**：同级仅剩 2 个面板时，删除项 `disabled`（PrimeVue Splitter 语义为多面板容器，规则 3 也以「默认 2 个」为准）。根 Splitter 的删除项同样 `disabled`。
3. **增删面板后的 `sizes`**：按原比例归一到合计 100（保留 2 位小数），长度始终等于面板数 —— PrimeVue 要求 `sizes` 与面板数对齐。
4. **新增面板单位默认 `%`**（与规则 3 的拆分默认一致），`sizeValue` 初始 0。
5. **根节点拆分落位用 `Object.assign(node, wrapper)` 原地替换**，避免改动 store 引用（`index.vue` 的 `layouts` 是同一对象引用，原地替换才能保证响应式与引用一致）。
6. **文案硬编码中文**（见第二节「其它约定」）。
7. **菜单仍是最外层实例唯一共享**（多实例会同时弹两个菜单，上一轮已实测）。
8. **`%` 取实测像素比例**而非直接抄 `sizes[index]`：gutters 占位使两者本就不完全相等，实测比例才能与 `px/vw/vh` 口径统一。
9. **标签只显示 `sizeValue + useUnit`**，不再同屏显示 `sizes[index]`（语义重复）。
